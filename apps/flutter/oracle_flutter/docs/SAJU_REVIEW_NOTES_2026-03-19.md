## 이번 검토에서 확인한 사항

### 1. 십성 계산 코드 안정성 이슈 수정
- 위치: `SajuService.calculateTenGod()`
- 문제: `switch (category)` 각 case에 `break`/`return`이 없어 Dart 정적 분석 및 컴파일 관점에서 위험.
- 조치: 각 case에 `break` 추가.
- 영향: 십성 계산 로직의 기본 안정성 확보.

### 2. 절기 계산 정밀도는 현재 구조상 근사치 수준
- `_solarTermDays`가 월별 고정 경계일 기반.
- `_getSajuMonth()`도 `연/월/일`만 사용하고 출생 시각, 표준시/지역, 실제 절기 시각을 사용하지 않음.
- 결과적으로 입춘/경칩/청명 등 경계일 출생자는 월주/년주가 틀릴 수 있음.

### 3. 대운 시작 나이는 현재 사실상 고정값
- `_calculateMajorCycles()`는 순행/역행은 반영하지만 `startAge = 4`로 고정.
- 실제 명리 계산의 핵심인 “출생 시점 ↔ 다음/이전 절기 간 거리”가 빠져 있음.
- 현재 대운은 참고용 데모 수준으로 보는 것이 정확.

### 4. 일간 강약 판정은 단순 오행 카운트 비율식
- 현재 반영 요소:
  - 동일 오행 수
  - 인성(나를 생하는 오행) 수
  - 월지 오행 보너스 +2
- 미반영 핵심:
  - 월령의 계절력 강도 세분화
  - 통근(지지/장간 뿌리)
  - 투간 여부
  - 관성/재성/식상 누수 정도
  - 합/충/형/파/해로 인한 실질 세력 변화
- 따라서 `신강/중화/신약`은 설명 보조용으로는 가능하지만 정밀 판단에는 부족.

## 권장 구현 순서

### Phase A — 정확도 기반 정비
1. `SolarTermProvider` 도입
   - 인터페이스: `DateTime getTermDateTime(int year, SolarTerm term)`
   - 초기 구현: 1900~2100 절기 테이블(JSON 또는 generated Dart map)
   - 추후 구현: 천문 근사식/외부 검증 데이터로 교체 가능

2. 년주/월주 계산 분리
   - `resolveSajuYear()`
   - `resolveSajuMonth()`
   - 입력: 출생 `DateTime`, timezone offset(optional)
   - 출력: 절기 기준 보정된 년/월 인덱스

3. 경계 케이스 테스트 추가
   - 입춘 전/후 1일
   - 각 월 절기 전/후 12시간
   - 출생 시간 null / 23시 / 00시 / 01시 케이스

### Phase B — 대운 현실화
1. `MajorCycleStartCalculator` 분리
2. 계산 규칙
   - 순행/역행 결정: 성별 + 년간 음양
   - 순행이면 출생 시점부터 “다음 절기”까지 시간 차이
   - 역행이면 출생 시점부터 “이전 절기”까지 시간 차이
   - 시간 차이를 일수/시수로 환산
   - 명시적으로 선택한 규칙 적용
     - 예: `3일 = 1년`, `1일 = 4개월`, `1시간 = 5일` 등
3. 결과 저장
   - `MajorCycle`에 `calculationBasis`, `startAgeRawDays`, `isForward` 추가 검토

### Phase C — 일간 강약 고도화
1. 점수 테이블화
   - 월령 점수
   - 통근 점수
   - 투간 점수
   - 인성/비겁/식상/재성/관성 가감점
2. 출력 변경
   - 단순 문자열 대신 내부 점수 구조체 사용
   - 예: `DayMasterStrengthResult(score: 61, label: '신강', factors: [...])`
3. UI/해석 반영
   - “왜 신강/신약인지” 2~3줄 설명 가능하게 근거 노출

## 부가 기능 점검 메모

### Tarot
- 카드 뽑기/저장 플로우는 구조상 무난.
- 현재 결과 요약은 카드 방향 비율 중심이라 해석 밀도는 제한적.
- 개선 후보: spread position별 종합 문장 생성.

### Fortune
- `FortuneDailyService`는 deterministic 일일 결과 생성 구조.
- 실제 사주/프로필과 직접 연결되지 않아 개인화는 약함.
- 개선 후보: 저장 payload에 생성 seed 기록, 프로필 연동 옵션 추가.

### Dream
- 원격 해석 연결 구조는 양호.
- 결과 화면의 “오늘 사주 영향 요약”은 실제 꿈 내용보다 단순 오행 요약 비중이 큼.
- 개선 후보: 사주 요약을 보조 문구로 축소하고 꿈 해석 본문과 연결.

### Face
- 원격 분석 실패 대비 fallback은 존재.
- 현재 “오늘의 관상 점수”는 관상 + 사주 + 만세력 점수를 평균한 임의 지표 성격이 강함.
- 개선 후보: 엔터테인먼트 지표임을 더 명확히 표기.

## 결론
현재 사주 엔진은 폐기 대상이 아니라, 구조는 유지하되 다음 3가지를 중심으로 재정비하는 것이 맞다.
1. 절기 정확도
2. 대운 시작 나이 계산 근거화
3. 일간 강약 판정의 점수화/설명 가능성 확보
