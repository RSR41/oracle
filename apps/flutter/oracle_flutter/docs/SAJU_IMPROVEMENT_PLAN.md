# SAJU Improvement Plan

## 목적
ORACLE 앱의 메인 기능인 사주 분석을 **사용 가능한 수준**에서 **신뢰 가능한 제품 수준**으로 끌어올리기 위한 개선 계획 문서.

---

## 현재 상태 요약

현재 사주 기능은 다음을 이미 지원한다.

- 프로필 입력: 이름, 성별, 생년월일, 출생시간
- 사주 계산: 년주 / 월주 / 일주 / 시주
- 추가 분석: 오행, 십성, 12운성, 신살, 대운
- 결과 표시 및 History 저장

즉, 단순 더미 기능이 아니라 실제 계산 엔진 기반 구조가 이미 존재한다.

다만 아래 영역은 보강이 필요하다.

- 절기 계산 정밀도
- 대운 시작 나이 계산
- 일간 강약 판단 정교화
- 합/충/형/파/해 반영
- 출생시간 미상 UX
- 저장 흐름 단순화

---

## 우선순위

## P1 — 즉시 개선

### 1. 절기 계산 정밀화
**문제**
- 현재 월주/년주 경계가 고정 근사값 기반
- 절기 경계 출생자에서 오차 가능성 존재

**현재 구현 위치**
- `lib/app/services/saju/saju_service.dart`
- `_solarTermDays`
- `_getSajuMonth()`

**개선 방향**
- 고정 일자 기반 근사 계산 제거 또는 축소
- 연도별 절기 테이블 도입 또는 실제 절기 시각 계산 방식 도입
- 최소한 입춘/월 절기 경계 오차 줄이기

**완료 기준**
- 경계일 출생자의 년주/월주 오차 감소
- 절기 기반 계산 로직 문서화

---

### 2. 대운 시작 나이 계산 개선
**문제**
- 현재 대운 시작 나이가 평균치 수준으로 단순화되어 있음
- 실제 명리학 기준과 차이 발생 가능

**현재 구현 위치**
- `lib/app/services/saju/saju_service.dart`
- `_calculateMajorCycles()`

**개선 방향**
- 순행/역행 외에 절기와 출생 시점 간 거리 반영
- 시작 나이 계산식 명확화
- 테스트 케이스 추가

**완료 기준**
- 대운 시작 나이가 고정값이 아닌 계산값으로 산출됨
- 기준 로직이 코드/문서에 설명됨

---

### 3. 저장 UX 개선
**문제**
- 프로필 저장과 사주 결과 저장이 분리되어 있어 사용자 혼선 가능

**현재 구현 위치**
- `lib/app/screens/tabs/profile_screen.dart`

**개선 방향**
- 프로필 저장 후 결과 저장 유도 개선
- 자동 저장 또는 저장 유도 메시지 추가
- 저장 완료 시 사용자가 상태를 명확히 인식할 수 있도록 개선

**완료 기준**
- 저장 흐름이 1회 사용으로 이해 가능
- 결과 저장 누락 가능성 감소

---

### 4. 출생시간 미상 UX 개선
**문제**
- 시주가 빠지는 이유를 사용자가 직관적으로 이해하기 어려움

**현재 구현 위치**
- `lib/app/screens/tabs/profile_screen.dart`

**개선 방향**
- “출생 시간을 모르면 시주는 제외된다” 안내 추가
- 정확도 차이에 대한 설명 제공
- 미리보기/결과 화면에도 보조 설명 제공

**완료 기준**
- 출생시간 미입력 상태에서 결과 차이를 사용자가 이해 가능

---

## P2 — 품질 고도화

### 5. 합/충/형/파/해 반영
**문제**
- 원국 상호작용 반영이 약해 해석이 평면적일 수 있음

**개선 방향**
- 최소한 지지충, 삼합, 육합 등 자주 쓰는 관계부터 반영
- 해석 생성 시 결과 반영

---

### 6. 일간 강약 판단 고도화
**문제**
- 현재 오행 카운트 중심 단순 판정

**개선 방향**
- 월령 가중치 강화
- 통근/투간 개념 일부 반영
- 단순 비율식에서 한 단계 상향

---

### 7. 종합 점수 의미 재정의
**문제**
- 현재 점수는 엔터테인먼트 성격이 강함
- 사용자가 절대적 운세 점수로 오해할 수 있음

**개선 방향**
- 점수의 의미를 “균형도/종합 경향” 등으로 명확화
- UI에서 오해 소지 줄이기

---

## P3 — 장기 확장

### 8. 양력/음력 선택 지원
### 9. 윤달 처리
### 10. 출생지/시간대 반영

이 세 항목은 장기적으로 필요하지만, 현재 단계에서는 P1/P2보다 후순위.
